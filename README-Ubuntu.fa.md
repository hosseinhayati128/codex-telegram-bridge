# ربات تلگرام برای Codex دسکتاپ اوبونتو

این بسته به چت‌های محلی همان حساب در Codex دسکتاپ وصل می‌شود. منو، اعلان‌ها، ارسال دستور، فایل و درخواست‌های بومی از کد مشترک ربات استفاده می‌کنند. وضعیت راه‌اندازی را با آزمون زیر روی دستگاه مقصد بررسی کن.

## راه‌اندازی

برنامهٔ رسمی ChatGPT Desktop را روی Ubuntu 24.04 یا 26.04 LTS نصب و یک بار باز کن. با حساب خودت وارد شو و دست‌کم یک چت محلی در Codex داشته باش. Node.js نسخهٔ 24.5 یا جدیدتر و بستهٔ `bubblewrap` لازم‌اند. نصب برنامه در [راهنمای رسمی اوبونتو](https://learn.chatgpt.com/docs/linux/linux-app) آمده است.

پس از قراردادن فایل بسته در `Downloads`، در ترمینال همان کاربر اجرا کن.

```sh
sudo apt install bubblewrap
mkdir -p ~/.local/share
tar -xzf ~/Downloads/codex-telegram-ubuntu.tar.gz -C ~/.local/share
cd ~/.local/share/codex-telegram-ubuntu
node --use-env-proxy ubuntu/setup.mjs
```

نصب‌کننده چت اول را از فهرست محلی انتخاب می‌کند و پس از بررسی محافظت پوشهٔ خصوصی، توکن را در ترمینال بدون نمایش می‌گیرد. پیام `/pair` چاپ‌شده را در چت خصوصی همان ربات بفرست. برای استفاده از همان توکن روی اوبونتو، قبل از جفت‌سازی سرویس ویندوز را با `stop-telegram-bridge.cmd` متوقف کن. برای اجرای هم‌زمان دو میزبان از دو ربات استفاده کن.

```sh
systemctl --user daemon-reload
systemctl --user enable --now codex-telegram-bridge.service
```

برای اولین اتصال، کارهای فعال در Codex اوبونتو را تمام کن، از برنامه کامل خارج شو و از پوشهٔ بسته `./start-codex` را اجرا کن. برای نشست‌های بعدی هم از همین راه‌انداز استفاده کن. سرویس با ورود کاربر بالا می‌آید و اتصال به چت‌ها پس از بازشدن برنامه برقرار می‌شود.

## بررسی روی دستگاه

پس از بازشدن Codex و دریافت پیام سرویس در تلگرام اجرا کن.

```sh
node ubuntu/doctor.mjs
```

`ready: true` اتصال تلگرام، ابزارهای برنامه و خواندن مشخصات چت انتخاب‌شده را تأیید می‌کند. این آزمون یک نوبت مدل اجرا نمی‌کند. سپس `/menu` و `/recent` را در تلگرام امتحان کن و یک پیام بی‌خطر به چت انتخاب‌شده بفرست. برای تأیید مسیر کامل، یک سؤال قابل پاسخ و یک فایل کوچک را هم در همان چت آزمون کن.

اگر مسیرها خودکار پیدا نشدند، نصب را با `--cli /مسیر/codex` یا `--app-tools /مسیر/server.mjs` اجرا کن. `--thread UUID` شناسهٔ چت اول را مشخص می‌کند. برای تصحیح این موارد، سرویس را متوقف کن و نصب‌کننده را با گزینهٔ مربوط دوباره اجرا کن. داده‌های خصوصی در همان پوشه می‌مانند.

در صورت خطا، نتیجهٔ doctor و خروجی این دو دستور برای تشخیص کافی است. توکن یا فایل `private/ubuntu-pairing.json` را ارسال نکن.

```sh
systemctl --user status codex-telegram-bridge.service
journalctl --user -u codex-telegram-bridge.service -n 30
```

برای توقف و حذف اجرای خودکار، `systemctl --user disable --now codex-telegram-bridge.service` را بزن. سپس برنامه را از راه‌انداز معمول خودش باز کن. برای بازگشت همان ربات به ویندوز، پس از توقف اوبونتو در ویندوز `start-telegram-bridge.cmd` را اجرا کن.

نسخهٔ ویندوز و نسخهٔ اوبونتو به تاریخچهٔ محلی میزبان خودشان وصل می‌شوند. انتقال فایل‌های تاریخچهٔ ویندوز کار جداگانه‌ای است. آزمون‌های قابل اجرا روی ویندوز و آزمون اتصال واقعی داخل Codex اوبونتو جدا هستند.

راه‌انداز پوشهٔ خصوصی ربات و سوکت‌های systemd کاربر را از دید فرایند Codex پنهان می‌کند. این بررسی برای خواندن مستقیم فایل و دسترسی به سرویس کاربر است. برنامه و سرویس با حساب کاربری یکسان اجرا می‌شوند. ورود Codex یا اتصال MCP که به keyring و D-Bus نیاز دارد، در این بسته نیازمند آزمون و سازگارسازی جداگانه است.
